# 多路独立评审型委派 · 同一份产出，几路各带一个视角

> 2026-09-22 从 SKILL.md「§六」整节拆出（**内容一条未删**，逐字搬运）。触发与入口见主 skill。

---


与§五同类但不是「读多份源」，是「**几路读同一份成品**」。要点：

- **派队之前自己先通读一遍并落盘**。先看小队结论再读＝被污染；自己那份写完再派，两边命中才能对照——**多路独立命中同一处才是信号**，一路提到多半是个人口味。
- **视角要互不重叠，且每轮换新角度**（第二轮＝补第一轮没派的视角，不是换个说法重报）。可迁移的一套：**普通读者**（读感／哪里想快进）／**文字编辑**（腔调／套话／重说一遍）／**内行**（对本专业的规范或人设）／**结构**（节奏／时间线／重复交代）／**自洽性**（前后矛盾、机制递进、空间与物理——**自造设定／奇幻类必派这一路**，它拓的是别路拓不到的「对不上」；任务书给它一份探针清单：**物件数量账**（同一物件出现几次、来路对不对）／**同一场戏里重复的标尺**（光、时间、天气报了两遍）／**空间高度与出入口**（从哪儿进、怎么上去、出口是不是来路）／视距与尺度前后一致吗）。
- **顺手加两问，产出便宜又锐**：① 单点读者信号——「**如果这不是朋友写的，我会在第几行放下**」，只给一个行号＋一个理由（比十条「节奏偏慢」有用）；② 节奏／结构那路要它给**逐节强度序列（1–5）**，回来跟自己设计的情绪曲线对表——**谷段读数对不上（设计 1.5、被读成 4）就是谷没压住**，这是可用信息，不是它判错了。
- **输出统一 schema ＋ 条数封顶**（如 6–9 条）：要求 JSON 字段 `file / line / quote / kind=问题|感受 / severity / note / advice`；不封顶收回来的是一堆杂感，不统一字段几路没法并表。
- **引文逐字＋报真实行号**，任务书里明写「不许改写、不许凭印象复述，拿不准回去重读」——与§三.1 配套：回来必走 `bin/quotecheck`。**行号基准＝当前版本**：稿件被改过（删行／合并）后行号会位移，旧清单的行号不可照抄——发任务时把**当前行数**写进 brief（如「`22` 1–551、`23` 1–1317」），回来先核行号落在范围内。**假未命中**：子代理常在片段尾部多带一个引号（`」`／`”`），机器不认，但「最相近行」就是原文那一行——人工确认即可，**别当编造**。
- 回来分三层再报：**实测数据**（能量尺的直接给数字）／**改得动的**（小改，不动结构）／**定调级（要用户拍）**（方向选择、身份／定位落差这类）——不分层，用户会把你拿不准的东西当结论。
- **各路原始条目全文单独落一档**：分层结论是给你用的，**原文是给用户看的**（实测用户专门要过「这几位读者的结论全文」）。回来就把每路的 findings＋impression **原样转写**进一份「全文档」（标清该路视角／依据／条数／引文核验结果），分层结论另落一档、互相引用；下一轮判「前轮已报／新命中」也靠这份全文。**当场落、别等**——委派的 live 日志会把长行截成 `…(+N chars)`，完整的 JSON 只在派发回来那条汇总消息里，隔一步就抳不回来了。
- 不采的条目**连理由一起写**，否则下一轮又被同一路提一遍。
- **「口味」与「硬伤」要分开算**：它报的“这个句式太多／标点偏离”是**判断**不是事实，先量同类已发布作品的基线再采信——实测某句式 0.66/千字、已发布中位 0.43、区间 0–3.87 → **在区间内就不算病**，偏离中位不等于缺陷；把它写成硬伤，下一轮就会照着一条假标准去改稿。同理，它报的数字（占比／配平／重复次数）自己复算一遍再进账。
- **跑第二轮／第三轮时怎么读结果**：前轮判「核后不采」的条目被新一轮再踩，是**那个装置没落地**的信号——升级为待用户拍，**别第三次照原判驳**；反过来，上一轮刚拍过的改动又被判病，也别自己回改，一并交用户。
- **角色小队（拿现成的角色档案当视角，比泛化视角更锐）**：让角色带着自己的性格去读，她会在**她那种人最在意的地方**先停下。挑人三条：① 代表读者——她能不能替目标读者说话；② 正对病症——性格压在病症上才有分辨率（藏东西的人懂「不给人看」，口不对心的人懂「否认与找补」，寡言的人懂「不说话的那一侧读者接不接得到」，日程控抓时间账，完美主义者当句读校对）；③ **带偏风险写明**：顺从／弱气型（不敢说不好＝审查价值为零）、靠运气／直觉型（抓不住结构）、独占欲强或创伤重的（会把故事读成她自己的线）、理论至上型（出「术语对、读感错」的清单）——后四类列「慎用」。取依据**逐字引档案**，别凭印象；角色自带的称谓／关系若与作品里的称谓重合，要在报告里注明这层会带来的偏向。

- **分批派（角色小队尤其适用）**：不必一次把名单撒完——**首批 3 路**各占一类（最可能出新东西的三路）→ 过**验收四道** → 才铺下一批；**同批不放同类**（两个口不对心会互相复读）；**止损线：某一批里一条前轮没有的新命中都没有＝这种视角是换皮，停止加批**，别为了跑完名单硬铺。
  - **验收四道**：① 引文零编造（`quotecheck`）② 每条行号指得回原文 ③ **不演人设**——用角色的口气写读后感却不带行号＝退回重写 ④ 至少一条前轮没有的新命中。
  - **角色任务书另加两条**：把该角色档案里 **2–3 条性格原文**贴进任务书（防它自创人设）；要求**自身偏移单列**（同类偏向／自身偏向／替她要东西——标了但**不算问题**，不许混进问题表）。
  - 同类位的产出和别路不同：她给的是「**干这行的人不会这么记**」那类内部账目（对还挂在墙上的画说「撕了」／同一件事的自述前后打架），泛化视角基本拓不到。

## 成品稿单路审读（用户说「派一个就行」时）· 隔离清单

**改动大了要重派一路终审**（2026-09-23 糖霜 ch20 实测）：第一轮抓 13 处（道具位移／时间线／状态互斥），修完后加厚了三段又重派一轮——**同一份任务书再抓 13 处**。第二轮的价值不在重复，在「改动带出来的新账」（新段落引入的时间倒序、新道具的来处、新写法的自报字数）。**每轮实质改动后重派，别指望第一轮覆盖**；两轮的清单＋逐条处置都要落进稿子旁边的账里。

**一路也照同一套任务书**——「一个人」是路数少，不是标准降；随手问一句收回来的是感想，不是清单。落盘、schema、封顶、引文核验一条都不省。

- **child 禁读内部档案**（大纲／逻辑链／改动单／前几轮评审记录／git 历史）。读了它就从**陌生读者**变成**合规检查员**：只会拿你已有的规矩把稿子再核一遍，拓不出「空杯喝不出烫」「某位女士凭空知道了价格」这类**只有新鲜眼睛才看得见的账**。任务书写死：只给①文件路径②作品前提（体裁／人称／哪些设定是真的）③要报的类型清单；明写「不要读该目录下的其他文件」。
- **只读、只出清单**：不许改任何既有文件、不许 git add/commit；产出清单落`scratch`（别落进项目档案目录，否则下一次它就成了「内部档案」）。
- **「找不到就写无」写进任务书**：只封顶不写这句，它会为了凑满条数把口味意见伪装成问题。另让它把「实在想提的风格观察」单独一栏、最多 3 条——问题表里不留风格建议。
- **要它自己核一遍引文**（断言「引文∈该行」）并在总结里报**通过条数／总条数**；**回来主代理重跑同一断言**（自报「12/12」不算验收）。
- **另收两栏**：① 它写不出来但觉得不对劲的「存疑」处（往往是最值钱的线索）② 它跑过的核验命令。回来分三层报（硬伤／读着别扭／存疑），**不采的连理由落档**。

### 给不给内部档案：两种读者，两种产出（派之前先选路）

- **空杯读者**（不给大纲／逻辑链／评审记录）：拓的是**新鲜眼睛才看得见的账**——物理、时间、因果。
- **对纲读者**（给大纲路径＋规则文件路径，并写明要求一类「**与大纲不符**」）：拓的是**规格漏落**——大纲里被反复强调的那一拍整条没写进正文，空杯读者永远不会报（实测：大纲里全篇强调的「抓住双肩」正文零处；「门响前她已坐直」只落了一半）。
- **两种产出不重叠，先决定要哪一路**；既要新鲜感又要合规就分两路、各给一套任务书，别一路两头都塞。两套都写死：**只读、只出清单、禁改稿**，**每条带行号与原文**。
- 与「child 禁读内部档案」不矛盾：那条讲的是**别让读者退化成合规检查员**（只会拿已有规矩再核一遍）；对纲读者是另一种活，**别拿它的清单去评价空杯那一轮的产出**。

### 新鲜读者稳定抓到的六类硬伤（自检清单，也是任务书里该点的类型）

| 类 | 判据 | 实测 |
|:--|:--|:--|
| **物象断线** | 同一件东西反复出现，每次位置／状态都要能接上；中间缺一个动作就是穿帮 | 便签先被扫到地上，后文又「压在便签一角」，中间没有捡起来的动作 |
| **同一拍写两次** | 一个状态（睡着／醒来／离开）只落一次；前一处写重了，后文就成了「搬动一个睡着的人」 | 「睫毛彻底不动了」被读成睡着，可后面还有倒水、说话、把人整个揽过来 |
| **台词与叙述打架** | 台词里指的东西必须与紧邻的那一段叙述是同一个 | 他看的是「天花板」，台词却说「还硬撑着看那块白墙」 |
| **来源缺失** | 每个动作都要有它的物：倒水要有水，点灯要有灯 | 「倒了半杯温水」——杯是容器，全篇没有水源 |
| **环境与状态打架** | 环境细节要跟当时状态一致 | 门还关着先写了「穿堂的风」；罩子还没拢，比喻先用掉「隔着一层布」 |
| **程度分级同款** | 做落差的两处不能用同一句形容，否则最深处那句没有比前面更低 | 两处低语都写「轻得连自己都听不太清」，「压在最底下」就失效了 |

> 机器红线（句法与统计）**这六类一概报不出**，作者自己的盲区也在同一处——**「红线全绿」之后才是派读者的时候**；审读回来逐条回原文核，改完重跑红线命令（新增内容会重新引入同类问题）。

## 六、多路独立评审型委派（几路读同一份成品，交问题清单）


> **派队之前自己先通读一遍并落盘**（先看小队结论＝被污染）；**视角互不重叠、每轮换新角度**；统一 schema ＋ 条数封顶；**引文逐字＋真实行号**（回来必走 `bin/quotecheck`）；回来**分三层再报**（实测数据／改得动的／定调级要用户拍）；**各路原始条目全文单独落一档**（分层结论给你、原文给用户）；**大改动之后重派一路新读者终审**（审读不是一遍就够：第一轮清干净后又做了加厚与标点，第二轮照样抓出一批同类型的硬伤——两轮的引文自报都是「全中」，仍要自己逐条回原文复核）。
> 15 条要点与实测（角色小队、分批派、验收四道、口味 vs 硬伤）→ `references/delegate-review-panel.md`。

**两路视角的固定配对（成品类：短篇／长文／卡片）**：

- ① **陌生读者（盲读）**——只给稿子与一句「这是什么体裁」，**不提任何已知问题**；要它报：哪里卡住／哪句看不出是谁说的或做的／哪句像作者在解释（出戏）／结尾第一感觉。schema 分栏，要求真实行号＋短引文。
- ② **细节连续性核对**——**必须随任务书给核对清单**（物品来路与部位／身体账先后／时间单向性／人数），它才会逐条核；不给清单，回来只会是「读着挺顺」。这一路最出硬伤。
- ③ **跨篇撞车／复用**——同一句话、同一个动作节拍（某个人的应答动作在新篇里出现十余次）、同一种句式被搬进新篇。**先上机器**：逐句对全库扫一遍（连续 ≥14 字重合即报），再让这一路**读同一场景族的旧篇**做人工复核——只问「读着顺不顺」抓不到它，机器也只看得见句子层，动作节拍与句式层要人看。
- **一篇至少派两路正交视角**（例：逻辑连续性 ／ 人设与文风撞车）：同一篇上两路的命中几乎不重叠，一路通读一篇会漏掉一半；**不要一路读完就收工**。
- **「受试」型委派**（让子代理**扮演／使用**一个产物并自评体验，而非审读它）：任务书 = 产物原文 ＋ 一组固定输入 ＋ 「先逐句产出，再如实报告：哪条规则最难守、哪里停下来权衡、顺畅度 1-5」，并**明写「如实报告比表现得好重要」**——不写它会把体面话当交付。**两个独立样本指向同一处才算真问题**；样本的**体感可信、对机制的推断不可信**（实测它把每轮固定注入的字段说成会滑出上下文，照收就会改错）。改了就用**同一套输入**复测才可比——分数掉了先分辨是产物变差还是测试变严（单轮→连问三轮，分数会掉）。
- **条数一多先机械分诊，再逐条判**：几路回来常是几十条意见，逐条读着核很慢且会漏。先跑一轮**四分类**（只靠 `grep` 就能做）：**旧疾**＝引文在当前稿里仍能找到｜**已修**＝引文已被改掉｜**新伤**＝本轮改动新引出的｜**无效**＝引文找不到、或找到了但判语读岔（相邻两段的先后看反、把两处并成一处）。工具链里有分诊子命令就先用它（例：`story triage`，先 `--help` 看参数）；分完只对「旧疾＋新伤」动手。
- **误报有固定形态**：引文确实在原文里，但**判语是它读岔了**（实测：报某动作与后文冲突，回原文两处本就在正确顺序上）——所以「引文能 grep 到」不等于「意见成立」。每条意见都要回到那一拍自己判一遍，再分流：**硬伤当场改／建议登记台账／与既定设计顶着的留给用户**（例：审读说「主角全篇没设局」，而大纲自己写的是「本篇人物被动」，改就是改调性——这类不采、登记等口径，并记下不采的理由）。
- **终审有两型，别只用一型**：**盲读终审**抓「还没被发现的病」；**改动清单终审**（把本轮每一处改动列出来，问「真对上了吗／改动带出什么新矛盾」）专抓**上一轮自己改出来的新伤**——实测后者抓到两处：把一件东西写进「箱子」里、可取用时还去抽屉找；给桌上报纸添了「被火烤过的痕」，而明火全程在另一处。**回改之后要跑的是后者。**
- **「既定写法」类的困惑归无效，别整批照改**：不交代人物名、不解释身世、独处篇里突然出现一个称呼——都是体裁约定，陌生读者一定会问，但那是设计不是缺陷；读感类（结尾快了一档／开头推力小）先判「是不是设计」，是设计就记放宽。

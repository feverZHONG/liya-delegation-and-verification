## 四、坑

- **审第三方报告（安全／运维／审计件）时，先做「文内算术自洽」，别急着翻原始数据。** 报告自己给的其它字段常能当场证伪它自己的结论：PID 增量 × 重启次数（PID 未绕回＝累计进程数有上限）、分项求和 vs 总数口径（被封 IP 合计 1192 vs「可疑 656」）、自称文件大小 vs 实际字节。成本几分钟，比要日志便宜一个量级，且对方无法推给「你看不到内部」。
- **「已升级到最新」只认发布记录，不认版本号大小。** 拿官方 news／releases 页核发布日期与分支归属（mainline 与 stable 是两条线，旧 mainline 会停在原地冒充「新」）；受影响区间按安全公告逐条比对版本，不要整体认也不要整体否——**同时交代哪些需要特定编译模块，否则会被「你不懂」反将一军**。（实测：被称「最新」的 nginx 1.29.8 发布于半年前，仍落 17 条公告区间，含 1 条 major。）
- **HTTP 200 ≠ 文件泄露。** 先请求一个必然不存在的路径做基线，比响应长度＋看正文；SPA 的 `try_files` 会把任何路径兜底成 index.html，只看状态码会把结论写反。同理，`Server:` 头能证版本号属实，但证不了「是否最新」。

- **任务书里给了「待验假说」，就必须要求它报假说的成立范围与反例** → `references/pitfalls.md`
- **「找不到」要给它一个合法的输出位**：schema 单列一栏置信度（确证／疑似／无证据），任务书写明「允许交『库内无证据』，不许为凑数编一条」。实测 16 条里 15 条有落点、1 条如实报空，回来抽验零编造——不写这一条，子代理会把空位用最像的答案填满。
- **`命令 | tail` 的退出码是 `tail` 的**：工具已经 exit 1、屏幕上还打着错，你照样会读到 rc=0 报「成功」。要看退出码就别套管道（或用 `set -o pipefail`）；要么干脆读回结果本身。
- **截段读工具报告＝把没看到的检查项当成通过** → `references/pitfalls.md`
- **名单里的「已选／已采／✅」不等于内容已进产物** → `references/pitfalls.md`
- **生成器的「刷新」＝覆盖手写件** → `references/pitfalls.md`
- **工具的「成功」也是自报** → `references/pitfalls.md`
- **子代理也会真抓到坑**：它报「别名撞车」「概率算错」这类，先当线索查，别因为「不归它管」就丢掉——顺手报上来的那几句常常比派它干的活值钱。
- **按固定格式读输入的工具，报 0 要当「假空」查，别当「内容不够」** → `references/pitfalls.md`
- **没验的别写成验过**：总结里没出现实测数字，就等于这件活没交付。补跑一条命令比补一句解释便宜。
- **减法 / 删条目类改动按「事实」核，不按「条」核（先补后删）** → `references/pitfalls.md`
- **自己上一轮写的归属表／对比表也是自报** → `references/pitfalls.md`
- **减法批次要留一份「被拦下的也带理由」台账**：按同一判据过一批对象（P 张卡、N 份稿）时，**被规则刻意不收的候选要连理由一起落档**——不记，下一轮会把它们当成漏写再补回来，一次减法的成果就守不住。台账一行四样：对象 → 拦下什么 → 为什么（哪一道规则）→ 出处。
- **多副本批量改要可重入** → `references/pitfalls.md`
- **改了源就要重出下游产物**：成品稿／索引／快照这类**由 CLI 生成**的件，别手改——改完源重跑生成器（自带「与源逐字一致」自校的更省事），并把同步副本一并核过（拼接逐行相等）。手改产物＝下次重跑就把它冲掉，交付时两份还分叉。
- **改「被引用文档」前先 grep 全库的锚点，锚点只归位、不重编号** → `references/pitfalls.md`
- **共同仓里的 `git add -A` 是危险动作：一律要求逐路径 add，并要它报「没碰的脏文件」。** → `references/pitfalls.md`
- **`git add` 里混进被 gitignore 的路径，会以非零退出中止 `&&` 链，提交根本没发生。** → `references/pitfalls.md`
- **两半互不相交的产物拼成一个单元后，整单元必须重跑那把尺。** → `references/pitfalls.md`
- **删除／归档类改动要单独跑一次门禁（幽灵路径）** → `references/pitfalls.md`
- **自己发出去的东西收回来之后：拿线上稿与本地源稿逐段 diff，别靠肉眼。** → `references/pitfalls.md`
- **「多篇作品通读 → 时间线／连续性整理」型：按篇（或按文件）切路，每路交一份「锚点表」，别交读后感。** → `references/pitfalls.md`
- **子代理交回的长产物（TSV／清单／表格）让它在任务书里就先落盘，别指望事后从 transcript 里捞** → `references/pitfalls.md`
- **两条判据打架时，任务书要替它拍；不拍就整层不做**：子代理碰上「引号内一个字不许改」与「某类标点必须压到线以下」这类冲突，会交回一句「请裁定」并把那一层原样留着（实测六路全部停在破折号，一处没动）。写法：二选一写死范围（收：只许改引号内标点、字词不动；不收：只清外层），并要它在回报里单列「因冲突没做的事」——那一栏就是你要补做的清单。
- **孩子不知道你的上下文**：任务书里重复它需要的背景（路径 / 约定 / 口径），别写「按之前说的办」。
- **它报「已完成」时先看它有没有真跑**：总结里的命令与数字对不上（条数不对、路径不存在）就是没跑，让它补跑或自己跑。
- **它说「我动了哪些文件」也是自报，落点是文件与数字** → `references/pitfalls.md`

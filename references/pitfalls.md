# 委派与验收 · 坑（判例 ＋ 实测）

> 2026-10-07 从 SKILL.md「§四 坑」把**长条目的实测细节**逐条搬出（**内容一条未删**）；SKILL.md 留每条的一句判据，扫读用。

### - · - 它说「我动了哪些文件」也是自报，落点是文件与数字

- **它说「我动了哪些文件」也是自报，落点是文件与数字**：批量派活后先 `git status --porcelain <自己那批目录>` 数一遍它真动了什么——实测有子代理把两份动过的文件说成「不是本轮的（mtime 更早）」，而 mtime 正落在它自己的运行窗口内；也有子代理没用指定的工具、自建脚本重造一遍。维持型（搬家／拆薄／重格式）任务再加一道：拿**原始备份**跑自己的守恒脚本，别读它交回的结论数字。**还要核它有没有写到任务书之外的落点**：实测子代理会把同一批改动同时写进「本地原件」与「仓库工作副本」，副本还停在旧中间态，于是下一次同步被工具直接拒绕（恢复法：备份 diff → `git checkout -- .` 重置 → 再同步；原件才是权威）——收工时对自己那批目录逐个 `git status`，别只看它报的文件清单。


### - · - 子代理交回的长产物（TSV／清单／表格）让它在任务书里就先落盘，别指望事后从 trans

- **子代理交回的长产物（TSV／清单／表格）让它在任务书里就先落盘，别指望事后从 transcript 里捞**：delegation 的 live transcript 会把长行折叠成「…(+N chars)」，几百行的逐条产出只剩前若干行且截在字符中间——事后再想把它写进文件，等于让它白跑一轮。任务书写死「完整产物落到 `<绝对路径>`，总结里只报**路径＋条数**」，验收直接读那个文件而不是读总结。


### - · - 「多篇作品通读 → 时间线／连续性整理」型：按篇（或按文件）切路，每路交一份「锚点表」，

- **「多篇作品通读 → 时间线／连续性整理」型：按篇（或按文件）切路，每路交一份「锚点表」，别交读后感。** 任务书写死三样：① 每条＝**逐字引文 ＋ `文件:行号` ＋ 类型 ＋ 一句解读**（引文回原文抄，禁止凭印象复述）② **不许写剧情梗概、不许写评价** ③ **找不到就写「无锚点」**，推测一律**显式标「推测」**。要求它**自己写脚本断言「引文∈该行」**再交——实测 5 路 312 条回来零编造、零行号偏差；主代理回来只做两件事：**先跑引文核验**（见 §三.1 表格式清单），**再把缺口表分「真缺」与「设计如此」两栏**——把用户已声明的写法（例：各篇本就是“不同时间段、特定时刻的片段”）混进缺口去报，等于拿用户的设定当缺陷，必被驳回。


### - · - 自己发出去的东西收回来之后：拿线上稿与本地源稿逐段 diff，别靠肉眼。

- **自己发出去的东西收回来之后：拿线上稿与本地源稿逐段 diff，别靠肉眼。** 发布物（专栏/文章/页面）会有**别人在发布环节顺手改的字**——真实删改点往往只有一两处、藏在几万字里，肉眼看一遍绝对看不出来，而「有意删」与「拼稿时掉了」要用它来分：**逐段 diff 之后逐处向用户报“这一处是有意的还是掉了”**，得到的口径再花一次钱也值（实测：全篇只差两处——一处是用户有意删的重复句，一处是拼稿时掉的尾巴）。写法：把两边按行归一（去空白与引号）后 `difflib.SequenceMatcher` 跑一遍，只打印非 equal 块（连同上下文），**自己那份只是对照组、不当基准**。


### - · - 删除／归档类改动要单独跑一次门禁（幽灵路径）

- **删除／归档类改动要单独跑一次门禁（幽灵路径）**：扫描器常按**暂存名单**取目标，而**已被删掉／移走的文件仍在名单里**——它读不到那个路径就报「挂」，于是「删一个旧候选」会变成「再也提交不了」（实测：把已换入的候选小样归到过程档后，`gate --changed` 仍把旧路径当目标判挂；同目录旧稿的 FAIL 数字还会被当成新稿的）。三条：① **换入完成后顺手把该单元的候选归档到过程档**（留在原 `小样/` 会被整目录扫，旧稿的 ❌ 行拖紧整个单元）；② 删／移后先自己跑一把 `--changed` 再提交；③ 报「挂」而文件已不在 = 幽灵路径，**先查名单不查稿子**。


### - · - 两半互不相交的产物拼成一个单元后，整单元必须重跑那把尺。

- **两半互不相交的产物拼成一个单元后，整单元必须重跑那把尺。** 按单元计数的项（同一个归属标签的上限、各类比例）在两半各自合规时，合起来照样超——实测两半拼好后同一个标签从 3 次变 4 次（上限 3），另有比例项因两半口径不同而位移。**别沿用半节的数字**；同理拼好之后要重跑**跨单元同句扫描**（两半原本分属两个单元时，重复句不在任何一边的检测范围内）。


### - · - git add 里混进被 gitignore 的路径，会以非零退出中止 && 链，提交根

- **`git add` 里混进被 gitignore 的路径，会以非零退出中止 `&&` 链，提交根本没发生。** `git add A B C && git commit …` 里只要有一个路径被忽略，屏幕上只滚过一行「The following paths are ignored…」，`&&` 就此停住——而随后的 `git log -1` 照旧打印**上一次**的提交号，看着像刚提交成功（实测如此：以为提了，`push` 报「已是最新」才发现）。动作：要 add 的路径先过一眼 `git check-ignore`，**把 `add` 与 `commit` 分开执行**，提交后**回读 `git log -1` 的标题**确认这一次就是本次的。


### - · - 共同仓里的 git add -A 是危险动作：一律要求逐路径 add，并要它报「没碰的脏

- **共同仓里的 `git add -A` 是危险动作：一律要求逐路径 add，并要它报「没碰的脏文件」。** 一个仓里常有别人（另一个会话、另一个子代理、后台任务）未提交的改动——`-A` 会把它们卷进 child 的提交，事后分不清哪一笔是谁的，还可能把别人半成品推上去。任务书写死：`git add <逐路径>`、不要 `-A`、不要 `git checkout/restore` 任何东西；回报里列一行「`git status` 里我没碰但脏着的文件」。回来自己核一遍 `git show --stat`：**只应有任务书里列过的路径**。


### - · - 改「被引用文档」前先 grep 全库的锚点，锚点只归位、不重编号

- **改「被引用文档」前先 grep 全库的锚点，锚点只归位、不重编号**：被脚本、兄弟 skill、项目文档引用的**节号**（`§四·七`、`p0-notes 九`）是硬锚点——章节可移位、内容可压缩，**编号不能重排**（实测：一个判据档的节号被本 skill 脚本十余处 ＋ 三个兄弟 skill ＋ 项目 README 同时引用，重排一次全部打歪）。先出清单：
  ```
  grep -rn "§\|第[0-9一二三四五六七八九十]*节" --include="*.md" --include="*.py" <库根>
  ```
  搬走某节时**在原位留占位标题**（`## 三、<原名>（已移出 → drafts/…）`）保编号连续，否则 mdcheck 报跳号、交叉引用失锚。


### - · - 多副本批量改要可重入

- **多副本批量改要可重入**：同一份稿子有多个同步副本（正文几篇 ＋ 工作稿）时，先用**一条命令把待改串在几个副本里逐一 grep** 核「存在且唯一」，再跑 patch 循环——`execute_code` 每次调用上限 **50 个工具调用**，边 check 边 patch 会在中途被截断。**中断后第一件事是重 grep 新旧串确认哪几条没落**；凭记忆接着改＝重复改／漏改。改完核同步：各副本去掉标题行与分隔符后的非空行，**拼接后逐行相等**才算同步。


### - · - 自己上一轮写的归属表／对比表也是自报

- **自己上一轮写的归属表／对比表也是自报**：拿它去铺开 N 份之前，先对着源逐条核一遍（每条断言要能指到具体字段名＋原文片段）。实测报出三处错：表里写的字段名是**旧术语**（对不上实际存在的那几列）、「删掉 X」里的 X 根本没出现过（空枪）、以及一条独有事实会被删走。**样板错一处乘 N**，铺开前自查一轮比铺开后返工便宜。**报「源里没有」之前先怀疑自己查错了位置**：一个字段查出来是空，可能是**同名嵌套一层**或平级改名（实测把 `extensions.depth_prompt` 里的 PList 判成「这份源没有该块」，据此写出的一整张归属表与一批对象的「内容很薄」结论全错）——空值先验路径再下结论；判反了要把下游基于它的产物**全部重出**，别只改被问的那一处。


### - · - 减法 / 删条目类改动按「事实」核，不按「条」核（先补后删）

- **减法 / 删条目类改动按「事实」核，不按「条」核（先补后删）**：删一条之前把它的内容拆成单条事实，**逐条找第二个载体**（别的字段／别的文件／别的条目）——指到「字段名＋原文」才算数。只要有一条事实只活在这条被删对象里，**先把它补进承接方再删**。整条判「已覆盖」是最容易吞信息的一步：删完那条独有事实就没人接了。


### - · - 按固定格式读输入的工具，报 0 要当「假空」查，别当「内容不够」

- **按固定格式读输入的工具，报 0 要当「假空」查，别当「内容不够」**：解析器（数条目、数表格行、数小节）多半严格认格式——输入写成「甲／乙／丙」一整段而不是列表，就报「0 条」；小节标题措辞差一个字，就报「0 环」。**动作：先看它认的标志长什么样（读那段解析代码，或照它自己的模板生成物写），把输入改写成模板的写法再跑一次**；连续两把尺都报 0，几乎一定是格式而不是内容。实测同一份单子：按模板重写后，两把尺立刻从「0 条／0 环」变成「✅ 填满」。**自己临时写的解析正则也吃格式**：行首正则要允许 markdown 强调符与代码符（`| **E1** |` 之于 `^\| E(\d+) \|` 就匹配不上，实测出现「核对 0 章、不符 0 章」的假全绿）——**解析前先剥 `**` 与反引号**；报「核对 0 条」时先拿一行样本手试正则，别当成内容缺失。


### - · - 工具的「成功」也是自报

- **工具的「成功」也是自报**：`patch`／写文件类调用遇到**不存在的旧串**会静默跳过（可能返回成功、也可能是 None），于是「改账」一轮轮都以为打上了、而那一行停在几轮前的旧值（实测：总账行停在十几个节次之前，期间每次「订正」都收到成功）。凡改账／回填数字：改前 `grep` 确认那条串**存在且唯一**，**改后立刻 `grep` 回读那一行**；总账一律**按源重算**（把各单元数字加一遍），不拿心里的数字去改。


### - · - 生成器的「刷新」＝覆盖手写件

- **生成器的「刷新」＝覆盖手写件**：带 `--write` 的生成命令（模板／骨架／索引刷新）会把**人已填好的同名文件整份换掉**（实测：手写填满的单子被模板覆盖，只能靠 `git checkout` 恢复）。三条：**填完就别再跑生成器**；要跑先确认 git 里有一版可回滚；手写内容与生成产物尽量分文件存。


### - · - 名单里的「已选／已采／✅」不等于内容已进产物

- **名单里的「已选／已采／✅」不等于内容已进产物**：把候选分批标成「采」「✅」之后，**收口前逐条 `grep` 回读产物**核落地（实测：一批 12 条「采」里有 3 条只活在名单上，产物里零命中）。同理，校验器报「✅ 填满」只证明**名单填完了**——那是形式判据，不证明产物里有，也不等于到顶。**名单采了而产物没有，比不采更糟**（下一轮会把它们当漏写再补一遍）。


### - · - 截段读工具报告＝把没看到的检查项当成通过

- **截段读工具报告＝把没看到的检查项当成通过**：检查器有十来项时，`sed -n '3,10p'` 只看到前四项 ✅，就会把后半段挂着的 ❌ 当不存在（实测：一条命令报「①②③ ✅」而后半段还挂着 ⑥ 两处、⑨ 一处，被当成「红线全归零」报了出去）。**要么读完，要么用 `grep -E "①|②|…"` 精确取项**；报「全绿」之前把每一项的名字逐个念一遍。


### - · - 任务书里给了「待验假说」，就必须要求它报假说的成立范围与反例

- **任务书里给了「待验假说」，就必须要求它报假说的成立范围与反例**——否则它会照着你给的假说把每一条都圆上（你说「顺序≈章节」，它就把 16 条全排成章节，还逐条配出处）。写法：明说「核实这个假说**成立到哪一段、哪里不成立**，允许答『局部成立』」。实测这样写，回来的是「只在第 5–10 位可核验，前 3 位与 11 位以后对不齐」——正好是要的边界，而不是一句「成立」。
